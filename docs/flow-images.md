# Google Flow images (image engine "flow")

Settings `image_engine` = `codex` (default) or `flow` (Settings tab, Tool settings, "Image engine"; or `workspace/settings.json`) is the default. The Run tab (Create & publish only) has a compact select "Images" (Codex / Google Flow) that starts at that setting and is for this run only: it fills the `{{IMAGES}}` line of the prompt, adds `--image-engine codex|flow` to the `pipeline.mjs create` command (which overrides the setting for that run and is kept in the run state for `--resume`), and Run now sends it to the app so the Playwright tools and the wait-for-Connect note follow the run's choice. Changing it never writes the setting. With `flow`
Create & publish does not run Codex for images: the agent (Claude Code) makes each image in Google Flow in the signed-in Chrome through the
Playwright MCP, then registers it with one command. Brand rules stay in the brand skill and in each draft's `prompt.txt` / `prompt-0N.txt`
(no logo on the product, text on images in English, album of 1 to 4 images): those files are the full (Codex-style) prompts; into Flow paste a CONDENSED version (see "Condensed prompt").

## Images per post
Every post is an album of 1 to 4 images of the SAME scene (`image.png` = cover, `image-02.png`, `image-03.png`, `image-04.png`). The count is random in `posts.images_per_post` (default `[1, 4]`). Customize: Settings tab > "Images per post" (min, max; `workspace/settings.json` `posts.images_per_post`), per brand `workspace/brands/<id>.json` `posts.images_per_post`, per run the Run tab (Create) two number fields "Images per post" min and max (1-4, default = the Settings range, 1 and 4) = `pipeline.mjs create --images N|min-max` (no flag when both equal the default; min = max gives `--images N` = exactly N; otherwise `--images min-max`; kept in the run state for `--resume`).

## Album type: other angles or other scenes
A post with 2 or more images is one of two types, chosen at random per post when the draft is created (`draft.mjs new`, default 50/50) and stored in `draft.json` `album_mode` (`angle` | `scene`, shown in the Posts overlay under "Album"; drafts without it count as `angle`). Image 1 (cover) is the same in both; a single image ignores it. The rules (consistency, the brand's scene table in project.md section 10) live in the skill: `references/image-guide.md`, "Album: góc khác hoặc cảnh khác".
- `angle`: same scene, a different camera shot per extra (detail, then wider/other angle). Prompt: `prompts/album-extra.txt`.
- `scene`: the same product (same text, colours, size) in a DIFFERENT scene per extra, picked per the brand's table, never a forbidden scene, different from image 1 and from the other extras. Prompt: `prompts/album-extra-scene.txt`. The scenes: the agent writes `album_scenes` (one line per extra) in the Stage B ideas entry (`pipeline.mjs` passes `draft.mjs new --album-scenes "a|b"`), or at Stage C writes the scene on the `NEW SCENE FOR THIS IMAGE:` line of `prompt-0N.txt` (kept when prompts are rewritten). The code cannot derive a scene; with none chosen, `flow-brief` says so (`warning_scene`) and the Codex extra fails with `{{ALBUM_SCENE}}` open.
- Forcing: Settings > Album (`workspace/settings.json` `posts.album_mode`: `random` default | `angle` | `scene`), per run the Run tab (Create) select "Album" (Random / Same scene, other angles / Other scenes) = `pipeline.mjs create --album angle|scene|random` (no flag when it equals the Settings value; kept in the run state for `--resume`; `draft.mjs new --album ...`).
- `flow-brief --n k` prints the condensed prompt of the post's type. `scene`: "Edit the attached image (image 1 of this post). Keep exactly the same product with the same text character for character (same shape, colours, materials, size); place it in a different scene: <scene>, natural light, candid photo look. Square 1:1 frame. No people, no other text, no logos." Stage C lists per draft `album_mode` and per image `make` (cover | same scene + shot | a different scene: <scene>).

## Google's sparkle
Every Flow picture carries Google's sparkle (a four-point star, bottom right). Its distance from the edges depends on the download size, measured on real files: 1K (1024 x 1024) centre about 103 px from the right edge and 97 from the bottom; 2K (2048 x 2048, Flow's upscaled download) centre 120 px from both edges, star about 48 px wide. So the remover finds the star on each picture: it tries every centre 90 to 130 px from the right and bottom edges (star radius 25.8 px at 1K, 25.0 px at 2K, in between by size) and takes the place where the inside of the star is brightest against the ring around it; it acts only when that contrast is clearly there (and not at the edge of the window), otherwise the picture is left unchanged. It is removed
locally by `scripts/image-unsparkle.mjs` (undoes the white veil, keeps the detail under it). Measured on the two real files: removed at (102,102) from the edges on the 1K and (120,120) on the 2K; a faint thin outline of the star stays visible on both when you zoom in. Never ask Flow to remove a watermark or change a brand
name: Flow refuses. A faint, thin outline of the star can remain on very textured or strongly JPEG-compressed areas: LOOK at the corner of every
image. The original download is kept next to the draft image.

## Commands
- `node scripts/image-unsparkle.mjs --image <png|jpg> --out <png>` prints `{"applied":true|false,"alpha":0.33,"right":102,"bottom":102}` (right/bottom = where the star centre was found). Input stays untouched; a picture without the star is returned unchanged (as PNG). Own copy of Product Review's remover plus a vendored JPEG decoder (`scripts/vendor/`).
- `node scripts/draft.mjs register-image --id <draft> --from <downloaded file> [--n 1|2|3|4]` (the one command per image): keeps the raw download (`image-generated-flow-original.jpg|png`, extras `image-02-flow-original.*`), converts to PNG (`image-generated.png`, extras `image-02-generated.png`), removes the sparkle, then the usual metadata clean (`image.png`, `image-02.png`, `image-03.png`), the watermark overlay when the brand has it on, and `draft.mjs check`. Works for a 1K or a 2K download (JPG or PNG). The metadata clean uses the remove-watermark skill script when `remove_watermark.script` exists, else the built-in cleaner (below). Status: `image_engine: flow`, `sparkle: removed|none` (per image in `flow_images`). A new call for the same `--n` puts the old image aside (`image-old-...`).
- `node scripts/draft.mjs flow-brief --id <draft> [--n 1..4]` prints the condensed English prompt for image n, the aspect ratio (1:1), the reference (the brand/reference photo for n=1, copied to `C:Users<user>Downloadssa-ref-<draft>-<n>.*`, nothing is removed; for n>=2 image 1 of the post, as it sits in the Flow project) and the register command.
- `pipeline.mjs create` with engine `flow`: Stage B does not start `image-batch`; Stage C answers `C waiting for Flow images` with, per draft, EVERY missing image (cover `image.png` and the album extras `image-02.png` ... `image-04.png`): n, prompt file (`prompt.txt`, `prompt-02.txt`, ...; the extras are written by the same album-extra logic as for Codex), `needs_image1_as_reference` (true for n>=2), the `flow-brief` command and the register command with `--n`, until every image is registered. A "redo" puts the old images aside and waits for new ones.

## Metadata clean: skill script or built-in
`config/settings.json` `remove_watermark.script` (default `../remove-watermark-skill/scripts/strip-png-metadata.mjs`, a path from the tool folder) is used when the file exists. When it does not (the skill folder is not on this machine), `scripts/image-clean.mjs` falls back to a built-in cleaner: for a PNG it copies only the picture chunks (IHDR, PLTE, IDAT, IEND, tRNS, iCCP, sRGB, gAMA, cHRM, sBIT, cICP, mDCV, cLLI; bytes unchanged, so the pixels are identical), for a JPEG it drops APPn/COM except JFIF and ICC and writes a PNG. The original is kept, `image-clean-report.json` has the same fields plus `cleaner: "built-in"`, and `status.json` `metadata_clean.cleaner` is `built-in` (or `skill`) so it is visible. Same rules as the skill: metadata only, no claim that AI detection is bypassed.

## Download size (`flow_download`)
In the Flow download menu: **1K "Kích thước gốc" (original) is the default** and is what the agent picks; **2K "Đã tăng độ phân giải" (upscaled)** is also fine (the remover handles both); 4K needs a plan upgrade. The size only changes where the star sits and how sharp the picture is; `register-image` takes either.

## Condensed prompt
`prompt.txt` is a Codex prompt (~6 KB, Vietnamese brand rules, last line "Save the result ... as image.png. Reply with only the file name."). For Flow paste a SHORT English prompt: what to keep, what to change, 1:1, no people/logos, and drop the Codex save line (`flow-brief` builds it from the draft). Worked on the first real run (2026-11-12): "Edit the attached photo. Keep the exact same scene: <scene>. Change only the text of the <sign>: replace \"<old>\" with exactly \"<new>\", in the same flowing single-line handwriting, same thin neon tube and soft glow, same position and size. Extend the scene naturally to a square 1:1 frame without stretching. No people, no other text, no logos." Flow does not reject a keep-scene text replacement like this. Album extras: "Edit the attached image (image 1 of this post). Keep the same product with the same text character for character, the same scene, the same lighting and the same moment; only a different camera shot: <detail: close-up of the product | wide: wider view or other angle>. Square 1:1 frame. No people, no other text, no logos."

## Timing
One image takes about 20-30 s; Flow renders several at once. So never submit one image and wait for it: submit everything, wait once, download everything. A post of 4 images in 3 posts = 12 images, about 2 waits of 30 s instead of 12.

## Procedure (Vietnamese Flow interface, plan PLUS; adapt if the language or layout differs; use text/role locators, never fixed coordinates unless unavoidable)
Setup (once per run, one Flow project per run or per brand):
1. Open `https://flow.google.com`. On the home page click the floating "Dự án mới" (New project) button.
2. The bottom prompt box ("Bạn muốn tạo những gì?") has chips: Tác nhân, model "Nano Banana Pro", an aspect icon and a count chip ("x4"). Click the count chip: a panel with Hình ảnh/Video, aspect ratios 16:9 4:3 1:1 3:4 9:16, the model, and x1..x4 (generation costs 0 credits on this plan). Choose Hình ảnh, 1:1 for feed, x1, press Escape. (x2..x4 makes variants of ONE prompt: use it only for that, never for different images.)

Batch, phase 1 (submit the covers of ALL posts, no waiting): for each draft, image 1 (`flow-brief --id <draft> --n 1`):
3. CLICK THE BOTTOM PROMPT BOX and paste the condensed prompt. Pitfall: the first `role=textbox` on the page is the PROJECT TITLE field at the top; typing there renames the project (if it happens, press the X next to it).
4. Reference image if any: the "+" button at the left of the prompt box, the upload button at the bottom-left of the picker, choose the file (the Playwright file chooser only reads under `C:UsersAdmin`: `flow-brief` already copied the reference from the tool workspace to `C:UsersAdminDownloads`; remove nothing). Say exactly what must stay.
5. Press the round arrow button at the right of the box and go straight to the next prompt (do not wait). Note the order (draft id, n) you submitted.
Then wait ONCE until every thumbnail is ready (about 20 to 30 s per image, they render in parallel).

Batch, phase 2 (album extras, only drafts with more than 1 image): for each extra n = 2..4 of each post (`flow-brief --id <draft> --n k`):
6. Click the bottom prompt box, then "+": the list shows the project's own results under the Tất cả / Hình ảnh tabs: click the thumbnail of THAT draft's image 1, then "Thêm vào câu lệnh". Paste the album prompt of the shot (detail / wide) and send; do not wait, go on to the next extra. Wait once more for all of them.

Batch, phase 3 (download and register, one by one):
7. Click a thumbnail (detail view; the prompt is shown there), click the download icon at the top right ("Tải nội dung nghe nhìn xuống"), pick "1K Kích thước gốc" (default; 2K "Đã tăng độ phân giải" is also fine; 4K needs a plan upgrade; see "Download size").
8. Chrome saves a JPG into the Downloads folder (download events are not delivered in extension mode and the Playwright sandbox cannot write files; Flow offers no PNG). The file name comes from Flow's own title (`<project name>_<id>.jpg`), NOT from our draft id: match it to its draft/image number by the order of the thumbnails or by the prompt in the detail view. With node/shell take the newest file in `C:Users<user>Downloads` right after each download, then `draft.mjs register-image --id <draft> --n <k> --from <that file>` (n = 1 image.png, 2 image-02.png, 3 image-03.png, 4 image-04.png). The command only reads the file (move or delete it afterwards if you like).
9. Repeat for every image, then `node scripts/pipeline.mjs create --resume` (the extras must come after their image 1: registering them in any order is fine, the album check passes when all files are registered).

## Stop rules
Login wall, captcha, a consent dialog the agent cannot pass, no credits, or a refusal from Flow: stop and report; do not retry endlessly. One browser = one agent: the agent drives Flow alone (submit all, wait once, download all; the Run now run waits for the person to click Connect in Chrome, same as Research).

## Run now
With the Images option of the Run tab on Google Flow (default = settings `image_engine`), a Create run started from the app allows the Playwright browser tools (`browser_tabs`, `browser_navigate`, `browser_snapshot`, `browser_click`, `browser_type`, `browser_press_key`, `browser_wait_for`, `browser_run_code_unsafe`, `browser_take_screenshot`, `browser_evaluate`, `browser_file_upload`) next to the create tools, and gets the same wait-for-Connect note as Research. With Codex nothing changes. The choice is per run: the Run tab sends it as `image_engine` in the `/api/agent-run` body and it wins over the setting.

## Run in the app (checklist)
- Create with Flow from Run now: Playwright browser tools + the wait-for-Connect note; `--add-dir` also covers the Downloads folder (the agent moves downloaded images from there); hard limit 45 minutes and up to 900 turns (settings `agent_run.timeout_minutes.create_flow`, `agent_run.max_turns`).
- Connect: the Welcome page of the chosen Chrome profile (Run tab > Chrome) must be clicked; if it is not, the run ends with "The Playwright extension did not connect" in the live panel.
- One browser = one agent: close any other session using the Playwright connect page first (the app cannot detect it; it only refuses a second headless run of its own).
- Never allowed in Create: Metricool write tools.
