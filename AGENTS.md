# social-autopilot – hướng dẫn cho agent

**Làm bài (ý, ảnh, caption): đọc `docs/LESSONS.md` trước** (bài học đã đúc kết: logo, nhãn AI, sản phẩm hợp bối cảnh, kích thước + tỉ lệ, scene-swap, caption, Metricool).

**Sửa/làm việc trên chính tool (code, test, UI): đọc `docs/MAP.md` trước** (thư mục, luồng dữ liệu, lệnh theo chế độ, nơi lưu trạng thái, luật, test nhanh, lỗi hay gặp).

File này là luật chung cho **mọi agent** (Claude Code đọc qua `CLAUDE.md`, Codex đọc trực tiếp; ChatGPT nhận qua prompt). Mọi việc qua các script Node trong `scripts/`: mỗi lệnh `node scripts/...` in một JSON (`ok`), chạy lại không sinh trùng, ghi vết vào `workspace/logs/<ngày>.log`. Không bước nào phụ thuộc một agent cụ thể; chỉ công cụ ngoài khác nhau (trình duyệt cho nghiên cứu, MCP Metricool cho bước gửi). **Scripts + `RUNBOOK.md` là nguồn duy nhất của quy trình**; prompt (tab Prompt, `docs/scheduled-prompt.md`) chỉ ngắn và trỏ về RUNBOOK. Tool chạy được trên mọi máy và mọi tài khoản Metricool: không hard-code đường dẫn tuyệt đối, id tài khoản, blogId hay thương hiệu.

## Ba chế độ
1. **Research only** (chạy riêng, vd mỗi tuần): **một đường duy nhất: Claude mở trang (hoặc URL tìm kiếm) bằng Playwright MCP, tự cuộn (`scrollBy` của `next.scroll`; `mouse.wheel` chỉ là dự phòng; chờ `research.scroll_wait_seconds`), tự quyết khi nào dừng, và đọc dữ liệu bằng MỘT script trích xuất** (một lần mỗi phiên chạy install.js = `collect.mjs install`; rồi mở trang (sau install), cuộn, chạy file nhỏ; `collect.mjs script` ghi file vào `research.script_dir` (`~/.playwright-mcp/social-autopilot`) và in đường dẫn → một lần gọi `browser_run_code_unsafe` với `filename`, không dán, chỉ đọc trang hiện tại, chỉ bài mới; phía Node của script gửi kết quả về app (token một lần, 5 phút; Token rule: run `collect.mjs script` again if it returns `saved:false` with HTTP 403 (the script file holds no secret; its Node side fetches a one-time token, 5 minutes, one use, from the app when it runs).) → `collect.mjs from-page` không cần `--b64`, cộng dồn vào `raw.json`; app phải đang chạy). **Reference sources are never skipped to save output: each gets its turn before discovery; skip one only with `result --state blocked|partial|known|end` and a reason. Login wall (Facebook or any site): `result --state blocked --note "login wall"`, go on with the other sources, and re-check that source ONCE at the end of that brand's run (Chrome may have been signed in meanwhile).** Một vòng = trích xuất → from-page → nhìn ảnh `review[]` và chạy `collect.mjs fit` ngay → đọc bộ đếm (`read`, `pending_fit`, `kept`, `rejected`, `need`, `need_more`) → quyết. Dừng: đủ `need` bài ĐÃ GIỮ sau fit (`need_more` 0), `poor_source` (đọc ≥ 3 × need mà vẫn thiếu), 3 lần trích xuất không có bài mới, mọi bài đã có, tường đăng nhập / captcha / trang đóng. Agent nhìn ảnh quyết `product_fit` (`collect.mjs fit`); script đọc thiếu bài thì xem DOM, sửa `SELECTORS` của adapter (`scripts/platforms/<nền tảng>.mjs`), trích xuất lại; kiểm xong đặt `status: "ok"` + ngày trong `scripts/platforms/index.mjs`. Thứ tự theo `research.mjs next`: (1) bài mới của **trang tham khảo** (`research.sources`), (2) chưa đủ mục tiêu (`--max-posts`) thì **tìm thêm** theo `research.discovery.keywords`/`hashtags` xoay vòng các nền tảng bật (Instagram, Pinterest, Facebook tìm bài/nhóm, Etsy, Houzz), **chỉ bài có sản phẩm đúng loại thương hiệu bán** (`product_fit`; sai loại không tải, không lưu) → `ingest --source|--query` (bỏ trùng trên mọi nền tảng) → `result` → lọc một lượt `store.mjs classify` + `verdict` → `report`. **Một trình duyệt = một agent** (Chrome đã đăng nhập qua Playwright MCP). Không làm ý/bài. Chi tiết từng nền tảng: `docs/research.md`. Không gõ lại kết quả: nếu script trả `saved:false` kèm `b64` thì truyền nguyên văn bằng `--b64`.
2. **Create & publish** (khi người dùng bảo; không mở Facebook): `getBrandSettings` → `metricool-mcp.mjs sync-brands` → gửi bài **đã duyệt** chưa gửi thành bài **hẹn giờ thật** (`payload` → `createScheduledPost` → `record`; không bao giờ nháp) → đối chiếu (`status` → `getScheduledPosts`) → `ideas.mjs` → `draft.mjs new/image` → caption → `draft.mjs check` (`ready` = **To review**) → **dừng** → báo cáo. Đường nhanh mặc định: `scripts/pipeline.mjs` (mcp-plan → create → điền ý một file → ảnh nền + contact sheet → viết caption một file → kiểm, queue, runlog; Mode 3: `pipeline.mjs publish`); các bước từng bước là dự phòng (RUNBOOK). Người dùng duyệt trong app (Approve = `finalize.mjs approve --id <draft>`: ghi vào sổ bài của tool `workspace/posts/<brand>/` + host ảnh); lượt sau hẹn giờ các bài đó.
3. **Publish approved** (Mode 3): chỉ hẹn giờ các bài **Approved** chưa gửi: `pipeline.mjs mcp-plan` → `pipeline.mjs publish --brand <id|all> [--limit N] [--window w] [--start today]` → gửi từng item ngay (`createScheduledPost` → `record`) → `pipeline.mjs publish --resume`. Start: From tomorrow (mặc định) / From today (`--start today`, chừa 15 phút; 1 bài/ngày chỉ giờ chính). Không làm bài, không mở trình duyệt.
4. **Nhật ký lượt chạy** (mọi chế độ, mọi agent): bước gần cuối luôn là `node scripts/runlog.mjs add --mode research|create|publish --agent "<agent>"` (RUNBOOK 1.5 / 2.9 / 3.1), rồi báo cáo với các mục cố định (1.6 / 2.10 / 3.2). Người dùng xem ở tab **Log**.

Trạng thái người dùng thấy (tab Posts, đúng thứ tự): **To review** (chờ duyệt) · **Approved** (đã duyệt, chờ gửi: chưa có id Metricool) · **Scheduled** (đã hẹn giờ trên Metricool: có id, không bao giờ gửi lại) · **Posted** (đã đăng); bài lỗi có dấu đỏ.

App (`start-app.cmd` Windows / `start-app.command` macOS → `src/server.mjs` + `ui/index.html`): Overview (brand Metricool + skill đã trỏ: Choose skill / Change skill / Disconnect), Library (kho), Posts (xem trước, Approve, Drop), Prompt (prompt ngắn theo chế độ × agent × thương hiệu), Settings. App chỉ gọi hàm của `scripts/`, không có logic riêng, không chạy các bước của agent.

## Kết nối Chrome
**Kết nối Chrome (một cách thống nhất):** (1) cài extension **Playwright MCP Bridge** trong profile Chrome muốn dùng; (2) app > tab Prompt, chọn profile đó ở dòng Chrome check; (3) bấm **Open Chrome (profile)**, lần đầu (và mỗi phiên) bấm **Connect** ở trang Playwright MCP Bridge; nếu agent báo chưa nối thì chạy `node scripts/chrome-connect.mjs --url "<url connect>"`, dừng và chờ người dùng bấm Connect rồi nói "connected"; (4) chạy Chrome check. Token là tùy chọn (chỉ bỏ bước bấm Connect). Không có đường dẫn riêng của máy nào: Chrome, profile và CLI `claude` được tự tìm; ghi đè bằng `research.chrome_path`, `research.chrome_user_data_dir`, `claudeCli.command` trong `workspace/settings.json`.

## Nguyên tắc
- **Chỉnh riêng trong tool** (tab Overview → Edit brand): `workspace/brands/<id>.json` `{ posts_per_day, paused, sources_add[], sources_disabled[] }` được trộn đè lên `social.json` của skill ở mọi chỗ tool đọc cadence/nguồn/enabled (`lib.mjs brandSocial`); skill không bị đổi. Lệnh: `social.mjs override --brand <id> --json '{...}'`.
- **Thương hiệu = brand Metricool trỏ tới một thư mục skill.** Skill **không bao giờ được chép** vào tool: `workspace/metricool-brands.json` ghi `skill_path` (đường dẫn là chuẩn; mục cũ chỉ có `skill_id` = `<skillsRoot>/<id>-skills`), tool chỉ **đọc** thư mục đó (luật, ảnh sản phẩm, dữ kiện thương hiệu). **Skill chỉ đọc: tool không bao giờ ghi vào thư mục skill** (không catalog, không thư mục bài, không social.json); mọi việc của tool nằm trong `workspace/` của tool. Thư mục skill hợp lệ có `SKILL.md`, `project/project.md`, `project/social.json`; chạy được (usable) khi `enabled: true` và `scripts/check-skill.mjs --tool-ready` của chính skill exit 0. Overview → Choose skill tìm trong thư mục nguồn (mặc định `skillsRoot`, vd `../vaniecom-workspace/skills`) sâu 2 tầng; lệnh: `skills.mjs list-sources [--from <dir>] | validate --path <dir> | link --brand "<tên>" --path <dir> | unlink --brand "<tên>"`. Disconnect chỉ bỏ liên kết, không đụng thư mục; từ đó không gửi gì của brand đó.
- **Brand Metricool** (`workspace/metricool-brands.json`, dạng `config/metricool-brands.example.json`, chỉ ở máy): đầu mỗi lượt Mode 2 agent gọi `getBrandSettings`, lưu JSON ra file, `node scripts/metricool-mcp.mjs sync-brands --from <file>`: giữ liên kết skill theo blogId, brand đã mất thành `removed: true` (không bao giờ là đích của payload/record/CSV). Mọi brand đều được làm bài khi đã trỏ tới một skill dùng được; brand chưa trỏ skill thì không.
- **Mọi thứ riêng thương hiệu đọc từ thư mục skill**: `research.sources[]`, `channels[]`, `language_policy` (`mode`, `review_langs`), `product_images` (`sources`, `ai_scenes_allowed`, `watermark`, `reference_redraw`), `caption_rules`, `cadence` (`posts_per_week`, `timezone`, `slots`), `metricool`. Tên trường theo chuẩn project-skill (mục "Khai báo social"). Tool không chứa nguồn, kênh hay dữ kiện thương hiệu nào; không nhánh code theo thương hiệu. Thương hiệu chạy nối tiếp; nguồn và kho không trộn.
- **Kho nghiên cứu** (`scripts/store.mjs`): `items.json` (`S0001`, `source_id`, `post_url`, `alt_urls`, `post_ids`, `posted_date`, `caption`, `images[]`, `image_sha1[]`, `image_phash[]`, `caption_hash`, `status: new|rejected` (Available / Removed, kèm lý do `note`), `uses[]` `{draft, idea, scene, product, sign_text, at}`, `last_used`, `used_by` lịch sử). Bài kho không bị dùng hết: dùng lại được nhưng phải khác cảnh HOẶC khác sign_text so với mọi lượt trước (keep-scene đổi chữ, new-scene đổi cảnh; cùng cảnh + cùng chữ + cùng sản phẩm bị chặn) (`store.mjs reuseProblems`); trạng thái Library: Available (còn dùng được, "new" hoặc "used N×") · Removed; bài chưa dùng trước, rồi ít lượt nhất sau cooldown `ideas.reuse_cooldown_days`; Removed (bị lọc, không hợp hoặc đã dùng đủ) không bao giờ được chọn, `images/`, `progress.json`, `duplicates.json`, `ideas.json`. `workspace/runs/<brand>/<date>/` chỉ là nhật ký crawl.
- **Không bao giờ lưu trùng**: `ingest` bỏ bài trùng với cả kho theo link/mã bài trên mọi nền tảng (Facebook, Instagram `/p/`=`/reel/`, Pinterest, Etsy, Houzz; cả `alt_urls`), SHA-1 ảnh, ảnh gần giống (dHash, `research.dedupe.image_distance`), caption giống hệt hoặc ≥ `research.dedupe.caption_similarity`; ghi `duplicates.json`. Agent bỏ qua bài có trong `known.json` trước khi tải.
- **Collector + adapter** (Mode 1): script trích xuất của `collect.mjs` chỉ đọc trang hiện tại (không bấm, không hover, không cuộn, không like/lưu/theo dõi/bình luận/nhắn tin/tham gia/đăng/đăng nhập); Claude tự cuộn, chờ `research.scroll_wait_seconds` giữa hai lần cuộn, gặp tường đăng nhập/captcha thì dừng và báo `blocked`. Adapter viết khi chưa có trình duyệt thì `status: "untested"`: chưa tin cho tới khi agent kiểm trên trang thật bằng Playwright MCP rồi đặt `ok` + ngày; sửa selector chỉ ở khối `SELECTORS` đầu file adapter. Không ghi token/cookie vào file.
- **Research không bao giờ chờ một nguồn lâu:** Time cap: at most research.source_minutes (default 3) per source/query; next / script / from-page / fit print elapsed and, over the limit, stop "time": record research.mjs result --state partial --note 'time limit', keep what you have, go to the next source. Fallback: If the extract script errors, or still returns 0 posts / total_on_page 0 after two EXTRA extracts (scroll once more between them) on a page that visibly has posts, STOP using the script for that source: read the page yourself (Playwright MCP snapshot, a small browser_evaluate, or a screenshot), write the posts you see in the same small JSON the script returns ({platform, url, tiles:[{id, url, image_urls, caption, author, date_text}]}, no checksum) and pass it to collect.mjs from-page --json '<that>' (the tool downloads the images, skips known posts, writes raw.json; verified:false is expected); then the same loop (look at images, fit, counters, stop rules, time cap). Facebook: open the page, scroll once with the scrollBy snippet BEFORE the first extract (the feed only renders after a real scroll); an empty first extract on a page that was NOT scrolled is expected, not a script failure, and does not count toward the two empty extracts of the fallback. Browser rules: start every browser_run_code_unsafe with `await page.bringToFront();` (a hidden tab never gets animation frames, so rAF-based waits and mouse.wheel hang); work in ONE tab: close tabs left over from earlier runs and open the source in a new tab; never use waitForFunction for page readiness (use waitForLoadState('domcontentloaded') with a short timeout, or waitForTimeout; if waitForFunction is unavoidable use { polling: 250, timeout: 10000 }); any single browser call that takes more than 30 s counts as stuck: stop using it and go on (fallback: read the page yourself). Scrolling: scrollBy first, page.mouse.wheel(0,900) only as fallback AFTER bringToFront (Facebook sometimes needs real scrolling to render its feed).
- **Nghiên cứu**: không giới hạn mặc định (`--max-posts` = mục tiêu mỗi thương hiệu; discovery tối đa `max_per_platform` mỗi nền tảng); nghỉ ngẫu nhiên 5-15 giây giữa mọi thao tác; chỉ xem (không like/lưu/theo dõi/bình luận/nhắn tin/tham gia nhóm); tường đăng nhập/captcha/checkpoint → dừng nền tảng đó (`result --state blocked`). Bài tìm thêm chỉ để học ý; scene-swap chỉ từ ảnh sản phẩm cùng loại. Bài sai loại ghi `workspace/store/<brand>/rejected.json` kèm lý do.
- **Ngôn ngữ**: ngôn ngữ đăng = `channels[].lang` của kênh bật; `language_policy.review_langs` chỉ để người đọc (`content-<lang>.txt`, catalog `review_captions`), KHÔNG BAO GIỜ vào bài đăng hay Metricool.
- **Không bao giờ gắn nhãn AI lên bài**: `draft.mjs check`, `finalize.mjs`, `metricool-mcp.mjs payload`, `metricool-csv.mjs validate` chặn (`aiLabelHits`). `instagramData.isAiGenerated` luôn `false`. `ai_disclosure` trong catalog chỉ để lưu vết nội bộ.
- **Không logo trên sản phẩm**: prompt ảnh luôn có NO LOGO; logo chỉ là watermark nhỏ ở góc, thêm sau (`draft.mjs watermark`), chỉ khi `product_images.watermark.enabled`.
- **Album ảnh**: mỗi bài số ảnh ngẫu nhiên trong `posts.images_per_post` (mặc định `[1, 3]`, đè theo thương hiệu ở `workspace/brands/<id>.json`). Bản nháp: `image.png` + `image-02.png`... (`prompts/album-extra.txt`: cùng sản phẩm/chữ/cảnh, khác cú máy); sổ bài: `image.png` hoặc `image-01.png` (bìa), `image-02.png`...; host đẩy mọi ảnh, `media_url` là danh sách; payload MCP `info.media` đủ link theo thứ tự, `mediaAltText` một alt mỗi ảnh. Chữ trên ảnh luôn tiếng Anh, không có `image-vn.png`/`image-en.png`.
- **Tham khảo chỉ là cảm hứng**: ý trừu tượng (`ideas.mjs` chặn chép 6 từ liền, số điện thoại, link, tên shop); ảnh vào Codex là ảnh của thương hiệu. Scene-swap chỉ khi `product_images.reference_redraw.enabled` (bắt `--brand-can-produce`, `confirm-clean`, caption không tên shop); sản phẩm luôn lấy từ ảnh tham khảo, xoá mọi logo/tên shop/watermark/điện thoại/giá; agent nhìn ảnh tham khảo: không có mặt người → `keep-scene` (giữ cảnh, chữ mới trên sản phẩm cùng ngôn ngữ chữ gốc), có mặt người → `new-scene` (cảnh mới, xoá hết người, giữ chữ; `confirm-clean --no-people`).
- **Kích thước + tỉ lệ**: prompt luôn có cỡ thật, vật so sánh kèm cỡ thật (`--compare`), giới hạn (sản phẩm ≤ 60% đồ bên dưới, ≤ 40% tường, chiếm 20-35% ngang ảnh; thương hiệu đổi được ở `product_images.size_limits`). Sau mỗi ảnh agent đo và ghi `draft.mjs size-check`; vượt thì tạo lại một lần với `reprompt --smaller N`; `check` chặn ảnh quá to.
- **Ảnh như đời thật**: prompt luôn có khối PHOTOREALISM (ảnh chụp ngẫu hứng, lệch tâm, ánh sáng hỗn hợp, vật liệu có dấu dùng, chi tiết đời sống, không render/showroom, người chỉ mờ/một phần, neon có quầng thật); ảnh còn trông dựng thì tạo lại một lần.
- **Làm sạch metadata** (`settings.remove_watermark.script`, đường dẫn tương đối, vd `../remove-watermark-skill/scripts/strip-png-metadata.mjs`): sau Codex, sau watermark, trước writeback; `image-generated.png` → `image.png` sạch; check không đạt khi điểm ảnh đổi hay còn metadata.
- **Duyệt bởi người**: trạng thái bản nháp `needs_prompt` → `generating` → `needs_caption` / `image_failed` → `ready` (To review) → `approved` (Approve: `finalize.mjs approve --id <draft>`, kiểm lại, `writeback.mjs` ghi sổ bài của tool `workspace/posts/<brand>/` (`catalog.json` + `<POST-xx>/`, `scripts/posts.mjs`): mục `approved`, ảnh sạch + caption, kiểm bài `posts.mjs check`, host ảnh) | `check_failed` | `rejected` (Drop, `finalize.mjs cancel`). Approve là đường DUY NHẤT để một bài vào sổ bài (số POST riêng của tool theo thương hiệu, sau số lớn nhất trong sổ và `archive/`); không có duyệt hàng loạt (`--brand`). **Agent không bao giờ tự Approve.**
- **Host ảnh** (`host-image.mjs`, settings `imageHost`): chỉ media của bài đã duyệt, lên repo công khai `social-autopilot-sources` (clone trong tool ở `imageHost.path`, mặc định `workspace/image-host`, repo git riêng; chưa có thì tự clone từ `imageHost.remote_url`), `<brand>/<yyyy>/<mm>/<post-id>.<ext>`; link raw `https://raw.githubusercontent.com/<owner>/<repo>/<branch>/...` (`imageHost.rawBase`), không dùng tên miền riêng. Raw trả `.mp4` là `application/octet-stream`; video qua MCP Metricool nên được (Metricool chép media) nhưng chưa test. Lỗi host không huỷ bài (`image_host.next`). `remove` chỉ sau khi bài đã đăng.
- **Metricool qua MCP** (Node không gọi Metricool): Claude Code dùng connector claude.ai "Metricool"; Codex: `codex mcp add metricool --url https://ai.metricool.com/mcp` rồi `codex mcp login metricool`; ChatGPT: connector Metricool, từ JSON `payload` người dùng dán. `payload` in đúng tham số `createScheduledPost` (`blogId`, `date` ISO kèm offset, `info` chuỗi JSON: `draft: false`, `autoPublish: true`, text chỉ ngôn ngữ đăng, `publicationDate` theo `cadence.timezone`). Không có `--draft`/`--schedule`. Bài không qua kiểm vào `blocked`, bài khác vẫn đi. `record` ghi `metricool.<network>` + `schedule` vào sổ bài của tool; **không bao giờ gửi hai lần**: bài đã có id sống không vào `payload`, `record` từ chối id thứ hai (trừ khi đã `posts.mjs unsend`); nháp cũ được gửi lại thành bài hẹn giờ (`replaced_draft`). Chỉ facebook/instagram; không `createScheduledPostForReview`.
- **Metricool CSV** chỉ dự phòng khi MCP không dùng được (`metricool-csv.mjs`, người tự import).
- **Settings** (`config/settings.json`, bản máy `workspace/settings.json`): đường dẫn tương đối với thư mục tool. Bí mật (token, password, cookie...) không bao giờ được ghi (ngoại lệ duy nhất: token Playwright MCP trong workspace/secrets/, ngoài git).
- **Chạy cùng lúc**: mọi đọc-sửa-ghi file chung qua `withLock` và ghi nguyên tử. Mọi `child_process` có `windowsHide: true`.
- Commit chỉ đứng tên người dùng của repo, không thêm dòng co-author của agent.

- Agents must never read, print or log the Playwright MCP token (`workspace/secrets/playwright-mcp.json`, `PLAYWRIGHT_MCP_EXTENSION_TOKEN` in the MCP config or `claude mcp get` output).

## Bài học đã đúc kết

Bài học được đúc kết thành nguyên tắc ngắn để áp dụng lần sau, không chép lời phản hồi hoặc kể lịch sử xử lý.
